# 易语言接入指南

把 `NetDoctorNative.dll` 接进易语言程序，十几个 DLL 命令声明 + 两三个辅助子程序就能用。

---

## 一、准备

1. 把 **`NetDoctorNative.dll`**（6.5 MB，只需这一个文件）复制到你的易语言程序目录
2. 确认你的程序是 **32 位**编译（易语言默认就是 32 位）
3. 建议**以管理员身份运行**（修复、优化、清理类功能需要）

自检：先在易语言里调用 `ND_Ping`，返回 `pong` 就说明 DLL 加载正常。

---

## 二、DLL 命令声明

在易语言的「**DLL命令**」表里逐个添加。
「在DLL库中的命令名」填 `ND_xxx`，「命令名」填你喜欢的易语言名字。

> **重要**：所有命令的调用方式都是 **`__stdcall`**（易语言界面里叫「标准」），
> 这是默认值，不用额外设置。

### 基础

| 命令名（在DLL中） | 返回值 | 参数 | 备注 |
|---|---|---|---|
| `ND_Ping` | 整数型 | 无 | 恒返回字符串 `pong` 的指针，用于自检 |
| `ND_Version` | 整数型 | 无 | 返回 JSON |
| `ND_Free` | 无返回值 | 无 | 释放缓冲区（可选） |

### 网络

| 命令名（在DLL中） | 返回值 | 参数 |
|---|---|---|
| `ND_DiagNetwork` | 整数型 | `dnsTest` 整数型 |
| `ND_FixNetwork` | 整数型 | `mode` 整数型 |
| `ND_FixDeep` | 整数型 | 无 |
| `ND_DnsBenchmark` | 整数型 | `applyBest` 整数型 |
| `ND_DnsRestore` | 整数型 | 无 |

### 清理 / 硬件 / 优化 / 系统

| 命令名（在DLL中） | 返回值 | 参数 |
|---|---|---|
| `ND_CleanScan` | 整数型 | 无 |
| `ND_CleanRun` | 整数型 | `namesJson` 整数型, `includeRecycle` 整数型 |
| `ND_Hardware` | 整数型 | `compact` 整数型 |
| `ND_OptList` | 整数型 | 无 |
| `ND_OptApply` | 整数型 | `namesJson` 整数型, `restore` 整数型 |
| `ND_Services` | 整数型 | `filter` 整数型 |
| `ND_Startup` | 整数型 | 无 |

**所有返回「整数型」的命令，返回值都是一个 UTF-8 JSON 字符串的内存地址**（不是易语言文本）。
必须按下面第三节的方法转换，**不能直接把返回值当文本用**。

---

## 三、辅助子程序（关键，先写这三个）

### 3.1 把 DLL 返回值转成易语言文本

易语言的文本型是 UTF-16，DLL 返回的是 UTF-8 的 C 字符串（以 `\0` 结尾），
所以要**先按长度取字节集，再转码**。

```e
.版本 2

.子程序 ND取文本, 文本型, , 把 DLL 返回的 UTF-8 指针转成易语言文本
.参数 指针, 整数型
.局部变量 长度, 整数型
.局部变量 数据, 字节集

.如果真 (指针 ＝ 0)
    返回 (“”)
.如果真结束

' 逐字节找 \0 结束符
长度 ＝ 0
.判断循环首 (指针到字节集 (指针 ＋ 长度, 1) ≠ { 0 })
    长度 ＝ 长度 ＋ 1
.判断循环尾 ()

.如果真 (长度 ＝ 0)
    返回 (“”)
.如果真结束

数据 ＝ 指针到字节集 (指针, 长度)
.如果真 (取字节集长度 (数据) ＝ 0)
    返回 (“”)
.如果真结束

返回 (编码_Utf8到Ansi (数据))
```

> 如果用的是**精易模块**，直接用 `编码_Utf8到Ansi (数据)`；
> 没有模块的话用系统支持库 `编码转换`：
> ```e
> .局部变量 转换, 编码转换
> 转换.转换 (数据, #编码_UTF_8, #编码_GBK, )
> 返回 (转换.取结果文本 ())
> ```


### 3.3 从 JSON 里取字段（简易版）

易语言没有内置 JSON 解析，两种做法：

**做法 A：用精易模块（推荐）**

```e
.局部变量 json, 类_json
json.解析 (JSON文本)
摘要 ＝ json.取通用属性 (“summary”, )
cpu名称 ＝ json.取通用属性 (“cpu.name”, )
```

**做法 B：纯文本截取（无模块时够用）**

```e
.版本 2

.子程序 ND取字段, 文本型, , 从 JSON 里取一个简单字符串字段
.参数 JSON文本, 文本型
.参数 字段名, 文本型
.局部变量 起点, 整数型
.局部变量 终点, 整数型

起点 ＝ 寻找文本 (JSON文本, “"” ＋ 字段名 ＋ “":"”, , 假)
.如果真 (起点 ＝ 0)
    返回 (“”)
.如果真结束
起点 ＝ 起点 ＋ 取文本长度 (字段名) ＋ 4
终点 ＝ 寻找文本 (JSON文本, “"”, 起点, 假)
.如果真 (终点 ＝ 0)
    返回 (“”)
.如果真结束
返回 (取文本中间 (JSON文本, 起点, 终点 － 起点))
```

> ⚠ 做法 B 只适用于**简单、不嵌套、不重复**的字段。
> 像 `items` 数组里的 `name` 会匹配到第一个，取值会串。
> 要遍历列表（比如列出所有优化项）**必须用做法 A 的 JSON 类**。

## 五、参数传 UTF-8 指针的正确写法

`ND_CleanRun` 和 `ND_OptApply` 的第一个参数是 **UTF-8 JSON 字符串的指针**，这是最容易踩坑的地方。

### ✅ 正确做法

```e
.局部变量 参数字节集, 字节集
.局部变量 指针, 整数型

参数字节集 ＝ 到字节集 (编码_Ansi到Utf8 (“["隐藏任务栏搜索框","关闭商店应用推广"]”))
指针 ＝ ND_OptApply (取变量数据地址 (参数字节集), 0)
```

关键三点：
1. **先转 UTF-8**（DLL 只认 UTF-8，直接传中文会乱码）
2. **存到局部变量**（必须是有生命周期的变量，不能是临时表达式）
3. **取变量数据地址**，不是取变量地址

### ❌ 错误做法

```e
' 错误 1：直接把易语言文本（UTF-16）当参数传 —— DLL 读到的是乱码
指针 ＝ ND_OptApply (文本变量, 0)

' 错误 2：用取变量地址而不是取变量数据地址 —— 多一层结构
指针 ＝ ND_OptApply (取变量地址 (字节集变量), 0)

' 错误 3：把临时结果直接传 —— 表达式结束后内存可能已失效
指针 ＝ ND_OptApply (取变量数据地址 (到字节集 (编码_Ansi到Utf8 (文本))), 0)
```

> 不确定字节集是否以 `\0` 结尾的话，自己在末尾补一个 `{0}`：
> ```e
> 参数字节集 ＝ 到字节集 (编码_Ansi到Utf8 (文本)) ＋ { 0 }
> ```
> 这样能兼容按 C 字符串读取的实现（当前 DLL 两种都能正确处理）。

## 六、把耗时功能放子线程（重要）

DLL 所有函数都是**同步阻塞**的。清理扫描要 2 秒、硬件检测要 4 秒、
一键修复要 10~30 秒 —— **直接在界面线程调用会让易语言窗口卡住不动**。

```e
.版本 2
.支持库 EThread

.子程序 _按钮_硬件检测_被单击
启动线程 (&线程_硬件检测, , )

.子程序 线程_硬件检测
.局部变量 指针, 整数型
.局部变量 JSON, 文本型

指针 ＝ ND_Hardware (0)
JSON ＝ ND取文本 (指针)

' 更新界面控件要回到主线程（易语言用 线程_进入许可区 / 或投递消息）
编辑框_结果.内容 ＝ ND取字段 (JSON, “report”)
```

耗时参考：

| 功能 | 耗时 |
|---|---|
| `ND_Ping` / `ND_Version` / `ND_OptList` | < 20 ms，可直接调用 |
| `ND_Startup` | < 1 秒 |
| `ND_DiagNetwork(0)` | 1~2 秒 |
| `ND_CleanScan` / `ND_Services` | 1~3 秒 |
| `ND_DnsBenchmark` | 2~4 秒 |
| `ND_DiagNetwork(1)` | 3~5 秒 |
| `ND_Hardware` | 2~5 秒 |
| `ND_FixNetwork(1)` | 10~30 秒 |
| `ND_FixDeep` | 30~60 秒 |

## 七、避坑清单

| 坑 | 说明 |
|---|---|
| **不能保存返回指针** | DLL 内部只有一块复用缓冲区。要把数据留下，**先 `ND取文本` 复制成文本**再存 |
| **先判断 `ok`** | 只要指针非 0 就当成功是错的。失败时也返回有效 JSON，必须看 `ok` 字段 |
| **`ND_Ping` 不是 JSON** | 它返回纯文本 `pong`，别拿去解析 |
| **`ND_FixDeep` 后必须重启** | DLL 不会自动重启电脑，要自己在界面提示用户 |
| **多线程要立刻复制文本** | 返回值指向 DLL 内部共享缓冲区，后一次调用会覆盖前一次。单线程（界面事件）调用无此问题 |
| **`ND_RestoreHosts` 不可逆** | 会清掉用户自己加的 hosts 条目，调用前务必二次确认 |
| **`highRisk` 项要二次确认** | 回收站清空后不可恢复；`note` 非空的项目有风险提示 |
| **`ND_OptApply` 的名称要一模一样** | 必须用 `ND_OptList` 返回的 `name` 原文（含中文顿号、括号等），差一个字就 `not_found` |
| **需要管理员权限** | 用 `ND_Version` 的 `admin` 字段自检。非管理员时修复/优化会部分失败 |
| **DLL 会往宿主目录写东西** | `.netdoctor\`（释放脚本）、`logs\`、`backup\`。注意你的目录是否可写 |
| **杀软可能提示** | DLL 会调用 PowerShell 和 netsh，属于正常系统命令，但个别杀软会拦。被拦时相关功能返回 `ok:false`，`error` 里有原因 |
| **x86 只能配 x86** | 这个 DLL 是 32 位。如果你的程序有 64 位版本，需要另编一份 x64（源码支持，改 `-r win-x64` 即可） |

## 八、想看完整效果，先跑自测宿主

不装易语言也能验证 DLL 是否可用。仓库里有现成的 x86 测试宿主：

```powershell
dotnet publish native-test/NetDoctorNativeTest.csproj -c Release -r win-x86
.\native-test\bin\Release\net10.0\win-x86\publish\NetDoctorNativeTest.exe
```

它会用**和易语言完全相同的方式**（`LoadLibrary` + `GetProcAddress` + stdcall 委托）
调用全部导出函数，输出每一项的实测结果，并验证异常处理不崩溃宿主。

另有压力测试宿主（专测异常路径）：

```powershell
dotnet publish native-test/StressTest.csproj -c Release -r win-x86
.\native-test\bin\Release\net10.0\win-x86\publish\NetDoctorStressTest.exe
```

它覆盖：非法指针（曾经的崩溃点）、页边界与跨页参数（曾经两次踩坑）、
畸形 JSON、参数极值、并发调用、缓冲区反复扩缩容、数据目录切换、

还有页边界探测工具 `native-test/CrashProbe.csproj`，用**独立进程逐个**验证
10 种指针布局（野指针、页尾无终止符、页尾+次页不可访问、跨页合法字符串等）
都不会让宿主异常退出。用独立进程是必须的：崩溃会带走整个进程，
同进程里连续测多个布局时，第一个崩掉后面的就再也测不到了。
