# 原生接口（NetDoctorNative.dll）—— 接口设计文档

给 **32 位易语言宿主**用 `LoadLibrary` 直接调用的原生动态库。
易语言工具箱不用改一行原有代码，加上十几个 DLL 命令声明就能用上网络诊断、断网修复、
DNS 择优、垃圾清理、硬件检测这些功能，**功能直接长在它的界面里**。

---

## 一、为什么是这个形态

| 约束 | 原因 | 对应设计 |
|---|---|---|
| 易语言是 **32 位进程** | 易语言 5.x 只有 x86 编译器 | DLL 编译为 `win-x86`（PE 机器类型 `0x014C`） |
| 易语言**加载不了托管 DLL** | 托管 DLL 需要 CLR 宿主，易语言没有 | 用 **NativeAOT** 编译成真正的原生 DLL，**宿主无需安装 .NET 运行时** |
| 易语言调用约定是 `__stdcall` | 易语言 DLL 命令默认 stdcall | 所有导出函数都用 `[UnmanagedCallersOnly(CallConvs = CallConvStdcall)]` |
| 易语言字符串类型简单 | 只有文本型（UTF-16）/ 字节集 | 统一返回 **UTF-8 JSON 的 C 字符串指针**，易语言侧读字节集再转文本 |
| 传复杂结构不方便 | 易语言没有结构体指针的便利写法 | 入参用 **UTF-8 JSON 字符串**，出参也是 JSON |

**实测结果**：`NetDoctorNative.dll` 大小约 **6.2 MB**，x86，
**17 个正式导出函数 + 1 个诊断导出**，在 x86 宿主里
`LoadLibrary` + `GetProcAddress` + 调用全部成功
（契约测试 32 项全绿、压力测试 30 项全绿、页边界探测 10 种布局无崩溃）。

## 二、构建与部署

### 构建

```powershell
cd NetDoctor

# 编译原生 DLL（需要 Visual Studio 的 C++ 生成工具 + Windows SDK）
dotnet publish native/NetDoctorNative.csproj -c Release -r win-x86

# 输出：native/bin/Release/net10.0/win-x86/publish/NetDoctorNative.dll
```

### 部署

只需要把这一个 **`NetDoctorNative.dll`** 放到易语言程序目录（或任意可写目录）。
首次调用时 DLL 会在**宿主 exe 所在目录**下创建：

```
.netdoctor\          ← 释放内嵌 PowerShell 脚本用（sysitems.ps1 / nettop.ps1）
```

日志与快照目录（调用 `ND_Services` / `ND_OptApply` 等涉及修改的功能后会出现）：

```
logs\                ← 运行日志
backup\              ← 改动前快照，可人工回滚
```

> 不想让 DLL 往宿主目录写东西？调用 `ND_SetDataDir("D:\某个文件夹")` 指定即可，
> 之后释放脚本、日志、快照都会落到该目录。传 `NULL` 可恢复为自动判定。

## 三、通用约定

### 1. 调用约定与命名

- 全部 `__stdcall`
- 全部导出名以 **`ND_`** 前缀，不与其它库冲突

### 2. 返回值

**所有函数返回 `const char*`（UTF-8 JSON）**，两种形态：

```json
{"ok":true,  ...业务字段... , "log":"执行过程的文字日志"}

{"ok":false, "code":"错误码", "error":"人话说明"}
```

- `ok` —— **必须判断这个字段**，不要只判断指针非空
- `code` —— 机器可判断的错误码（见附录）
- `error` —— 直接可以显示给用户的说明
- `log` —— 本次调用产生的日志文本，可直接写进易语言的日志框，便于排查

### 3. 内存与生命周期

- DLL 内部持有**一块复用的缓冲区**，返回的指针在**下一次调用本 DLL 任意函数之前**有效
- **不需要**调用方分配或释放内存
- `ND_Free()` 可选：想主动释放就调，不调也不会泄漏（下次调用会复用同一块）
- ⚠ **不要在多线程里同时调用，除非每次调用后立刻把文本复制走。**
  返回值指向 DLL 内部的同一块缓冲区，后一次调用会覆盖前一次的内容 ——
  这是「共享缓冲区」设计的固有性质。易语言在界面事件（单线程）里调用不会遇到；
  若确实要多线程用，请在每个线程内「调用 → 立刻转成易语言文本」，不要跨调用保存指针。
- ⚠ **不要在两次调用之间保存返回的指针**。要留数据就先复制成易语言文本

### 4. 入参

- 字符串入参一律传 **UTF-8 的 JSON**，易语言里用 `编码_Ansi到Utf8` 或 `到字节集` 后取指针
- 需要传数组时用 JSON 数组字符串，例如 `["隐藏任务栏搜索框","关闭商店应用推广"]`
- 传 `0`（空指针）时按"空/默认"处理，**不会崩溃**
- 字符串必须**以 `\0` 结尾**，长度上限 **1 MB**（超出部分截断，不会报错）
- 非法指针（野地址、未映射地址、指向不可读区域的指针）一律**按空串处理**，
  统一走 `{"ok":false,...}` 返回，**不会崩溃宿主**

> **为什么这点要单独强调**：入参读取走的是内核校验（`ReadProcessMemory`），
> 它逐页确认整个范围可读，任何一页不可读就整块失败。
> 曾有两版实现在这里踩过坑 ——
> 只校验起始页会让「字符串从页尾开始」的布局直接把宿主进程干掉；
> 按页整块读取又会把 `\0` 之后的字节一起带回，尾部多余 NUL 让 JSON 解析抛异常，
> 表现为「参数传对了、功能却毫无反应」。两种情况现在都有自动化回归测试覆盖。

### 5. 阻塞与线程

**所有函数都是同步阻塞调用**，请在易语言的**子线程**里调用耗时功能，否则界面会卡住：

| 函数 | 典型耗时 |
|---|---|
| `ND_Version` / `ND_Ping` / `ND_OptList` | < 20 ms |
| `ND_CleanScan` | 1~3 秒 |
| `ND_DiagNetwork(0)` | 1~2 秒 |
| `ND_DiagNetwork(1)` | 3~5 秒（含 DNS 实测） |
| `ND_DnsBenchmark` | 2~4 秒 |
| `ND_Hardware` | 2~5 秒 |
| `ND_Startup` | < 1 秒 |
| `ND_Services` | 1~2 秒 |
| `ND_FixNetwork` / `ND_FixDeep` | 10~60 秒 |
| `ND_OptApply` | 按项数，每项 50~500 ms |

> 实测参考（i7-14700KF）：硬件检测 4.2 s，网络诊断 1.5 s，清理扫描 1.9 s。

### 6. 权限

部分功能需要管理员权限。`ND_Version` 会返回 `admin` 字段告诉你当前是不是管理员。
非管理员时：

- `ND_DiagNetwork` / `ND_Hardware` / `ND_CleanScan` / `ND_OptList` —— 仍可用
- `ND_FixNetwork` / `ND_FixDeep` / `ND_OptApply` / `ND_CleanRun` —— 会部分失败，日志里能看到

## 四、函数清单

| 函数 | 用途 | 是否需要管理员 |
|---|---|---|
| `ND_Ping` | 自检 DLL 是否加载成功 | 否 |
| `ND_Version` | 版本与运行环境 | 否 |
| `ND_DiagNetwork` | 网络诊断（分层连通性 / DNS 实测 / 代理探测） | 否 |
| `ND_FixNetwork` | 断网修复（轻量 / 一键） | **是** |
| `ND_FixDeep` | 深度修复（重置 Winsock/TCP-IP） | **是** |
| `ND_DnsBenchmark` | 12 个公共 DNS 测速，可选自动应用最快的 | 否 / 应用需**是** |
| `ND_DnsRestore` | 恢复自动获取 DNS | **是** |
| `ND_CleanScan` | 扫描各清理目标占用（只读） | 否 |
| `ND_CleanRun` | 执行清理 | **是** |
| `ND_Hardware` | 硬件检测 | 否 |
| `ND_OptList` | 枚举 151 项 Windows 优化的当前状态 | 否 |
| `ND_OptApply` | 应用 / 还原指定优化项 | **是** |
| `ND_Services` | 枚举服务及启动类型 | 否 |
| `ND_Startup` | 枚举启动项及启用状态 | 否 |
| `ND_Free` | 释放返回缓冲区 | 否 |
| `ND_RestoreHosts` | 单独还原 hosts（⚠ 危险，见下方说明） | **是** |
| `ND_SetDataDir` | 指定数据目录（释放脚本/日志/快照的落点） | 否 |

`ND_RestoreHosts` 会清掉用户自己加在 hosts 里的所有条目（广告屏蔽、内网域名映射等），
不可逆，**请在宿主界面里明确提示并二次确认后再调用**。

### 诊断导出（非正式接口）

| 函数 | 用途 |
|---|---|
| `NDX_ReadString(p)` | 只做「指针 → 字符串」，返回 `{"raw":"读到的内容","len":长度}` |

它不做任何业务处理，存在的意义是**把「入参读取」和「业务解析」分开测量**：
业务接口返回 `code:empty` 时，光看返回值无法判断是"读不到字符串"
还是"读到了但解析不出来"。定位尾部 NUL 污染那次，就是靠它一眼看出
`raw` 里混进了 `\u0000`。

**不属于正式对外接口**，后续版本可能调整或移除，业务代码不要依赖。
`ND_FixDeep` 刻意不包含 hosts 还原，就是为了避免这种无提示的信息丢失。

### ND_DiagNetwork

```
const char* ND_DiagNetwork(int dnsTest);
```

| 参数 | 说明 |
|---|---|
| `dnsTest` | `0` 只做连通性检查（快）；非 `0` 额外实测每个 DNS 服务器（慢 2~3 秒） |

```json
{
  "ok": true,
  "adapters": [
    { "name": "以太网", "type": "有线", "desc": "Realtek PCIe GbE Family Controller",
      "up": true, "ipv4": "192.168.1.3", "mask": "255.255.255.0",
      "gateway": "192.168.1.1", "dns": "192.168.1.1",
      "dhcp": "自动(DHCP)", "speed": "1000 Mbps", "mac": "XX:XX:..." }
  ],
  "gateway": "192.168.1.1",
  "checks": [
    { "name": "本机协议栈 (127.0.0.1)", "level": "Ok",   "detail": "TCP/IP 协议栈可正常收发", "hint": "" },
    { "name": "默认网关 (192.168.1.1)", "level": "Ok",   "detail": "0 ms", "hint": "" },
    { "name": "外网 IP 可达",           "level": "Ok",   "detail": "最快 223.5.5.5 → 5 ms", "hint": "" },
    { "name": "DNS 域名解析",           "level": "Ok",   "detail": "www.baidu.com → 36.152.44.132  (4 ms)", "hint": "" },
    { "name": "HTTP 出网",              "level": "Ok",   "detail": "HTTP 200  (41 ms)", "hint": "" }
  ],
  "dns": [ { "server": "192.168.1.1", "ok": true, "ms": 1.2, "note": "" } ],
  "proxy":      { "enabled": true, "server": "127.0.0.1:7897", "pac": "" },
  "proxyProbe": { "bad": false, "detail": "代理 127.0.0.1:7897 正在监听（代理软件已开启）" },
  "system": [
    { "name": "hosts 文件", "level": "Ok", "detail": "无自定义条目（正常）", "hint": "" }
  ]
}
```

**`level` 取值**：`Ok`（绿）/ `Warn`（黄，建议处理）/ `Bad`（红，异常）/ `Info`（灰）

**`checks` 固定 5 项**，顺序就是排查顺序：协议栈 → 网关 → 外网 → DNS → HTTP。
哪一层开始变红，问题就在那一层。

**`proxyProbe.bad` 为 true 时最值得注意** —— 说明系统代理指向本机但端口不通，
这是"能上 QQ 打不开网页 / 代理关了以后全网打不开"的最常见原因。

### ND_FixNetwork

```
const char* ND_FixNetwork(int mode);
```

| mode | 行为 | 耗时 |
|---|---|---|
| `0` | 轻量：刷新 DNS + 关闭并重置系统代理 | 2~5 秒 |
| `1` | 一键修复：刷新DNS → 修169.254 → 清ARP → 关代理 → 拉起网络服务 | 10~30 秒 |

```json
{ "ok": true, "mode": "quick", "log": "..." }
```

**改前会自动写快照**到 `backup\backup.ini`。

---

### ND_FixDeep

```
const char* ND_FixDeep(void);
```

深度修复：**重置 Winsock 目录 + 重置 TCP/IP 协议栈** + hosts 还原 + 清 ARP + 关代理 +
拉起服务 + 重新获取 IP。

```json
{ "ok": true, "needReboot": true, "hostsTouched": false, "log": "..." }
```

**不含 hosts 还原**（`hostsTouched` 恒为 false）—— 还原 hosts 会清掉用户自定义条目，
属于不可逆的信息丢失，因此单独放在 `ND_RestoreHosts` 里，由宿主自行确认后调用。

> ⚠ **`needReboot` 恒为 true。** Winsock 与 TCP/IP 栈的重置**必须重启电脑才完全生效**，
> 重启前网络可能不稳定。**DLL 不会自动重启电脑**（不弹窗、不执行 shutdown），
> 请在易语言界面里自己提示用户。
>
> 修复期间网络会中断数次，建议先提醒用户保存工作。

### ND_DnsBenchmark

```
const char* ND_DnsBenchmark(int applyBest);
```

并发实测 12 个公共 DNS（阿里 / 腾讯 / 114 / 百度 / CNNIC / 360 / Google / Cloudflare / Quad9）。

| 参数 | 说明 |
|---|---|
| `applyBest` = `0` | 只测速，不修改任何设置 |
| `applyBest` ≠ `0` | 测速后自动把最快的写入所有活动网卡（**改前写快照**） |

```json
{
  "ok": true,
  "results": [
    { "name": "CNNIC DNS", "ip": "1.2.4.8",  "ok": true, "ms": 5.2,  "note": "" },
    { "name": "阿里云 DNS", "ip": "223.5.5.5", "ok": true, "ms": 6.1, "note": "" },
    { "name": "Google DNS", "ip": "8.8.8.8",  "ok": false, "ms": null, "note": "超时无响应" }
  ],
  "best":    { "name": "CNNIC DNS", "ip": "1.2.4.8", "ms": 5.2 },
  "applied": true
}
```

`results` 已按「可用优先、延时升序」排好，取第一项就是最快的。

{
  "ok": true,
  "items": [
    { "name": "系统临时文件", "group": "临时文件与缓存", "bytes": 812953,
      "size": "793.95 KB", "commandOnly": false,

    { "name": ".NET 程序集缓存(NativeImages 64)", "group": "临时文件与缓存",

### ND_CleanRun

const char* ND_CleanRun(const char* namesJson, int includeRecycle);

### ND_OptList

```
const char* ND_OptList(void);
```

枚举全部 151 项 Windows 优化的**实时状态**（读注册表判定）。

```json
{
  "ok": true,
  "total": 151,
  "applied": 83,
  "notApplied": 68,
  "categories": [
    { "id": "xingneng", "title": "性能优化", "hint": "提升响应速度与流畅度…", "count": 45 }
  ],
  "items": [
    { "name": "隐藏任务栏搜索框", "category": "explorer",
      "applied": false, "unknown": false,
      "current": "2", "target": "0", "highRisk": false }
  ]
}
```

| 字段 | 说明 |
|---|---|
| `applied` | **条目级**：当前是否已经是优化后的状态 |
| `unknown` | true 表示无法自动判定（整键存在性判定类），共有 1 项 |
| `current` | 注册表当前值（`(未设置)` 表示值不存在） |
| `target` | 优化后的目标值 |
| `highRisk` | true 表示会降低系统防护（关防火墙 / 关内存完整性 / 关虚拟化安全 / UAC 从不通知），**界面上应标红并默认不勾** |

`categories[].id` 就是 `items[].category`，可用来自建树形或标签页。

### ND_OptApply

```
const char* ND_OptApply(const char* namesJson, int restore);
```

| 参数 | 说明 |
|---|---|
| `namesJson` | UTF-8 JSON 字符串数组，元素必须是 `ND_OptList` 返回的 `name`**原文** |
| `restore` = `0` | 应用优化 |
| `restore` ≠ `0` | 按配置里声明的方案**还原为 Windows 默认** |

```json
{
  "ok": true,
  "mode": "apply",
  "succeeded": 5,
  "failed": 0,
  "failedNames": [],
  "needExplorerRestart": true
}
```

- **改前自动记录每一项的注册表原值**到 `backup\backup.ini`
- `needExplorerRestart` 为 true 时，任务栏 / 右键菜单 / 主题类改动需要重启资源管理器才可见
- 单项失败不会中断整批，失败清单在 `failedNames`，明细在 `log`

### ND_Services

```
const char* ND_Services(const char* filter);
```

| 参数 | 说明 |
|---|---|
| `filter` | 关键词，匹配服务名或显示名；传 `0` 或 `""` 返回全部 |

**默认只返回第三方服务**（自动排除 `System32` 下的微软自带服务），避免列表太长。

```json
{
  "ok": true,
  "count": 38,
  "items": [
    { "name": "AsusCertService", "display": "ASUS Certification Service",
      "running": true, "status": "运行中", "startType": "自动", "startNum": "2" }
  ]
}
```

`startType` 是**直接读注册表 `Start` 值**得到的真实类型（自动 / 手动 / 已禁用 / 延迟自动），
比 WMI 的 `StartMode` 更准确。`startNum`：`2`=自动 `3`=手动 `4`=禁用 `5`=延迟自动。

### ND_Startup

```
const char* ND_Startup(void);
```

枚举注册表 `Run`/`RunOnce`（HKCU + HKLM + WOW6432Node）与启动文件夹项。

```json
{
  "ok": true,
  "count": 4,
  "items": [
    { "name": "Steam", "source": "当前用户 · Run",
      "command": "\"D:\\Steam\\steam.exe\" -silent",
      "enabled": true, "kind": "Run" }
  ]
}
```

`enabled` 读取的是 Windows 官方的 **StartupApproved** 状态，与任务管理器显示一致。

> 当前版本只做**枚举**。禁用/启用启动项需要写启动文件夹或 StartupApproved，
> 属于修改类操作，暂未导出（可用主程序的界面版）。

## 六、错误码

| code | 含义 | 处理建议 |
|---|---|---|
| `exception` | 内部异常，`error` 里有原始信息 | 把 `log` 和 `error` 一起反馈 |
| `not_found` | 传入的优化项名称一个都没匹配上 | 名称必须与 `ND_OptList` 的 `name` 完全一致 |
| `empty` | 传入了空数组或空指针 | 先让用户勾选 |
| `nothing_to_clean` | 传入的清理项名称没匹配上 | 名称要与 `ND_CleanScan` 的 `name` 一致 |

**入参层面不会崩溃宿主。** 传错指针、传非法 JSON、传越界参数，
统一走 `{"ok":false,...}` 返回。

这一条由三层自动化测试守着，不是口头承诺：

| 测试 | 覆盖内容 |
|---|---|
| 契约测试（32 项） | 每个导出的正常与畸形入参行为 |
| 压力测试（30 项） | 野指针、页尾无终止符、跨页参数、并发、缓冲区完整性 |
| 页边界探测（10 种布局） | 独立进程逐个探测，**任何一次崩溃都会被 CI 拦住** |

> 页边界探测必须用**独立子进程**逐个跑：崩溃会带走整个进程，
> 同进程里连续测多个布局时，第一个崩掉后面的就再也测不到了。

## 七、已知限制

1. **必须有 PowerShell 5.1**（Windows 10/11 自带）。
   硬件信息、服务/启动项/计划任务枚举依赖它。
   若被安全软件拦截，这些调用会返回 `ok:false`，`error` 里会写原因。
2. **只做枚举的服务与启动项不能通过 DLL 修改**（修改类功能目前只导出优化项与清理）。
3. **`unknown:true` 的优化项**（1 项）无法自动判定当前状态，可以照常应用/还原。
4. **`ND_FixDeep` 后必须重启**，DLL 不会替你重启。
5. **多线程共享缓冲区**：返回值指向 DLL 内部同一块内存，并发调用会互相覆盖；
   请「调用后立刻复制文本」，或改为单线程调用（易语言界面事件即属此类）。
6. **`ND_SetDataDir` 只在进程内生效**，宿主重启后需重新设置。
7. **返回值指针不要跨调用保存**。
8. **必须在子线程调用耗时函数**，否则易语言界面会卡住。
